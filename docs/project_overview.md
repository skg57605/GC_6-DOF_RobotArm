# GC 6-DOF Robot Arm — 프로젝트 개요

ROS 2 Jazzy (Ubuntu 24.04) + ros2_control + MoveIt 2 기반 6축 로봇팔 제어 프로젝트.
(상위 구조는 유동적이며, 하드웨어 계층은 상위 프레임워크와 독립적으로 설계한다.)

---

## 1. 하드웨어 구성

### 1.1 관절 / 모터 매핑

| 관절 | 모터 | CAN ID | 모터 내장 감속 | 외부 감속 | **총 감속비** (모터축 : 관절) |
|---|---|---|---|---|---|
| J1 | MKS SERVO57D CAN | 1 (0x01) | – | 직결 1:1 | **1** |
| J2 | CubeMars AK45-36 v3.0 | 101 (0x65) | 36:1 | 4:1 | **144** (액추에이터 출력 기준 4) |
| J3 | CubeMars AK45-36 v3.0 | 102 (0x66) | 36:1 | 2:1 | **72** (액추에이터 출력 기준 2) |
| J4 | MKS SERVO42D CAN | 2 (0x02) | – | 직결 1:1 | **1** |
| J5 | CubeMars AK45-10 v3.0 | 103 (0x67) | 10:1 | 18/7 ≈ 2.571428571:1 | **≈25.714** (액추에이터 출력 기준 18/7) |
| J6 | MKS SERVO42D CAN | 3 (0x03) | – | 직결 1:1 | **1** |

- AK 액추에이터가 보고하는 위치는 **액추에이터 출력축 기준**이므로, 소프트웨어에서는 외부 감속비(4, 2, 18/7)만 적용한다:
  `q_joint = θ_actuator_out / ratio_ext`
- J5 외부 감속비 2.571428571은 18/7로 보고 정확한 유리수로 다룬다 (누적 오차 방지). → 실제 기어 잇수 확인 필요.
- MKS 엔코더: 16384 count/rev, 직결이므로 `q_joint = count / 16384 × 2π`.

### 1.1.1 모터 작동 모드

- AK (J2, J3, J5): Servo 모드 → **위치-속도 루프(mode 6, `SET_POS_SPD`)** 사용 예정 (현재 시험은 위치 루프 mode 4).
  속도 제한·가속도 제한으로 급격한 목표 점프 시 안전 확보 + 감속도 제한으로 회생 에너지 억제. 향후 MIT 모드 전환.
- MKS (J1, J4, J6): **SR_vFOC** (시리얼/CAN 제어 폐루프 FOC)

### 1.2 CAN 버스

- 어댑터: **CANable 2.0 Pro** → SocketCAN `can0` (gs_usb/candleLight 펌웨어 가정)
- 버스: 단일 버스에 6개 모터 전부 연결 (현재 J3·J5·J4/J6 계열로 혼합 구동 시험 중)
- 비트레이트: **1 Mbps 통일** (MKS 기본값이 다를 수 있으므로 모든 MKS를 1 Mbps로 설정)
- 프레임 구분
  - MKS: 표준 11bit ID (1, 2, 3). ID 0은 브로드캐스트 → 사용 금지
  - AK Servo 모드: 확장 29bit ID = `(mode << 8) | id`, 피드백 `0x2900 | id`
  - AK MIT 모드: 표준 11bit ID (0x65~0x67) — 전환 시 응답 ID를 `candump`로 확인
- 종단저항: 버스 양 끝단 120Ω만, 중간 노드는 해제. GND 공통.
- 버스 부하 목표: 1 사이클 = 6 명령 + 6 응답 = 12 프레임 → **제어주기 100~200 Hz** 목표

```bash
sudo ip link set can0 up type can bitrate 1000000
candump -tz can0
```

### 1.3 전원

- 24V 14.6A (350W) SMPS × 2
  - **SMPS-A**: J2, J3 (AK45-36 × 2) 전용
  - **SMPS-B**: J1, J4, J5, J6 (MKS 57D/42D, AK45-10)
- 두 SMPS의 **V− 공통 (한 점, 굵은 선)**, V+는 절대 병렬 연결하지 않음. 모터 전원 귀환 전류는 각자 SMPS로.
  CAN 배선은 CAN_H/CAN_L + 신호 GND(가는 선)를 꼬아서 함께 배선 (모터 전류가 CAN GND로 흐르지 않게).
  SMPS FG는 접지. CANable 2.0 Pro 절연 여부 확인 (비절연 시 PC USB GND가 로봇 GND에 연결됨).
- ⚠️ **회생 에너지**: AK 모터 급감속/중력 하강/외력 역구동 시 발전된 에너지가 DC 버스로 역류 → SMPS는 흡수 불가 →
  전압 상승 → SMPS OVP 차단(팔 낙하) 또는 드라이버 손상 위험.
  대책: (1) 소프트웨어 감속도 제한, (2) 분배점 벌크 커패시터(50V급, 수천 µF) + 돌입전류 대책,
  (3) TVS(순간 서지), (4) 필요 시 브레이크 초퍼(전압 비교 + MOSFET + 저항), (5) 오실로스코프로 실측 검증
- ⚠️ 비상정지: 모터 전원 차단형 E-stop 권장 (소프트웨어 정지와 별도)
- J2/J3 브레이크 유무 확인 필요 (전원 차단 시 처짐)

## 3. 원점(홈) 전략

- 각 관절에 **리밋 스위치** 설치 예정
- 초기 단계: 수동 자세 정렬 후 소프트웨어 영점(오프셋 저장)으로 개발 진행
- 이후: 관절별 저속 호밍 시퀀스 → 스위치 검출 → 오프셋 적용
  - 스위치 배선 위치 결정 필요: MKS 드라이버의 리밋/홈 입력 단자 활용(J1, J4, J6) vs 별도 MCU/IO 보드(AK 관절 J2, J3, J5)

## 4. 소프트웨어 구조

### 4.1 언어

- **C++17** 통일: ros2_control 플러그인이 C++ 필수이므로, 드라이버 라이브러리를 C++로 작성하여
  단독 테스트 툴과 하드웨어 플러그인이 **같은 코드**를 공유한다.

### 4.2 패키지 구성 (ROS 2 workspace `src/`)

```
gc_arm_description/      URDF/xacro, 메시, ros2_control xacro
gc_arm_hardware/         ros2_control SystemInterface 플러그인
  ├─ can/                 SocketCAN 래퍼 (단일 소켓, 버스 공유)
  ├─ drivers/ak_motor     CubeMars AK (Servo 모드 → MIT 모드 확장)
  └─ drivers/mks_motor    MKS SERVO42D/57D
gc_arm_tools/            단독 테스트 CLI (Phase 0)
gc_arm_bringup/          launch, controllers.yaml
gc_arm_moveit_config/    MoveIt 2 설정
```

### 4.3 설계 원칙

- 하나의 SystemInterface가 `can0` 소켓을 독점하고, 모터별 드라이버는 공통 `IMotor` 인터페이스를 구현
- AK 드라이버는 **제어 모드(Servo / MIT)를 파라미터로 선택**할 수 있게 추상화
- ROS 단위: rad, rad/s, Nm. 감속비·방향·영점 오프셋은 파라미터화
- `mock_components` 전환 옵션으로 하드웨어 없이 개발 가능
- 컨트롤러: `joint_state_broadcaster` + `joint_trajectory_controller` → MoveIt 2

### 4.4 미결 설계 이슈

- MKS 관절 명령 방식: 절대위치 명령(0xF5)은 내부 가감속 프로파일이 있어 고주기 스트리밍 시 끊김 가능
  → **속도 모드(0xF6) + 외부 위치 루프** 방식과 비교 시험 필요
- 직결 스테퍼(J1 57D)의 토크 여유 확인 (팔 전체 관성 부하)
